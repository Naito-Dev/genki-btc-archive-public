# 過去記録の扱い

旧方式の保存原本は変更しません。新方式の記録とは別に表示し、後から計算した結果で過去の判定を置き換えません。

基準にした公開リポジトリのコミットは `f60194683fbf7c92ba50e6ddcd519aa38883c807` です。最終記録日は2026-09-20です。

## 表示する区分

- **旧方式の計算履歴**：旧Model Dなどの理由を持つ公開履歴です。再計算された履歴を含み、記録の日付に実際に公開されたことを保証するものではありません。
- **公開判定の生成根拠未確認**：`private_current_signal` の公開記録です。元の計算成功・失敗の理由が公開用データに残っていません。CASHであることだけでは計算失敗と扱いません。
- **同日の詳細記録に計算失敗時の代入値**：同じ日の詳細ログに `MINIMAL_MODE: regime unavailable` と `data_source=unavailable` が明記されています。公開結果と詳細ログは別の実行で生成されているため、同一の生成結果であるとは断定しません。
- **CSV計算記録・入力鮮度未確認**：`data_source=csv` と計算理由が残っていますが、現在の方式による正常な日次判定とは扱いません。
- **後付け価格データ**：`HISTORICAL_BACKFILL` と明記された入力用履歴です。当日に出た判定ではありません。

2026-09-20までの詳細集約 `data/log.json` は、後付け価格履歴3,090件、計算失敗時の代入値を明記した212件、CSV計算経路の記録がある3件です。CSV記録の日付は2026-02-21、02-23、02-24です。02-21はDRY_RUNかつDATA_STALEであり、正常計算済みとみなしていません。

`logs/*.json` の209件は全件に代入値の理由が残っています。公開用 `private_current_signal` 196件のうち、2026-03-08はBTC、残り195件はCASHですが、この状態だけから原因を断定しません。

## 原本の不一致

- 個別日次と集約では2026-02-19、02-25、02-26、02-27に差があります。原本を統合したり、どちらかで上書きしたりしません。
- 詳細集約にある2026-02-19、03-26の公開用記録はありません。
- 2026-03-08の公開BTCは、同日の詳細ログの代入値・配分0と一致しません。
- `data/btcsignal_log_live.json` は2026-03-06で止まった旧版です。03-06が2件あり、ルートの公開用 `btcsignal_log_live.json` と同一視しません。
- 2017年からの後付け価格データと、運用開始後の日次判定の履歴は区別します。

これらを理由に元ファイルの削除、修正、ハッシュ再生成、Git履歴の書換えは行いません。監査ラベルは静的サイトの派生データだけに付けます。

## 公開する項目

旧方式のサイトには日付、当時の公開状態、元の理由、公開時刻、監査区分とその根拠を載せます。詳細ログから使う項目も配分・記録上のposition・理由・入力元・実行状態に限定します。口座残高、資産評価額、損益、取引履歴、Webhook、トークン、環境変数は公開サイトの出力に含めません。

新方式は検証済みの固定記録から表示します。Webでシグナルを再計算せず、同じ `record_id` と `result_sha256` を表示します。公開する入力は同じ記録が参照する検証済みの100本のOHLCVです。失敗は `status/latest.json` として分離し、最後の正常な記録を現在の判定に見せかけません。

サイトは生成済みHTML・CSS・JSONのみです。閲覧による市場APIへのアクセス、シグナル計算、注文、Workflow起動、フォーム送信はありません。
